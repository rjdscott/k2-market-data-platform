# Audit: phase P0, prerequisites and guardrails, 2026-11-26

**Verdict:** P0 delivered what its Exit line names: an ingest that finds the writer lock held
exits 75 and a test asserts it, every caller agrees, the CI compose job prints its sums and
fails above the ceiling, the six snapshots `tests/parity/pinned.json` names are tagged on the live lake with matching
ids, the release-check smoke queries name tables that exist, and every
published port listens on loopback only. Several of the guardrails it added, though, pass while
violating what they guard. The parity pin stops being a pin at the first nightly maintenance on
or after 2026-12-03, because the resolver walks `main`'s parent chain and never reads the tags
P0 created to keep the pin alive; the known-gap mechanism checks that its audit reference is
well formed, never that the row exists; the synthetic-data gate is a file-name filter; and the
branch protection's required checks do not bind the one account that merges every pull request.
The one BLOCKER is the posture of the system of record: the never-expired raw archive has one
copy, and any container on the engine can delete it without a credential (Lakekeeper
`allow-all`, hard deletes) or with MinIO's factory-default root pair, which is still live and
whose designed replacement is not on the remote. Before the next tag: bind the required checks
to admins, resolve pins by tag, query the audit row, keep a copy of `raw` outside the engine,
and widen `check-env.py` to the credentials it does not look at.

## Security posture

Every published port was confirmed on `127.0.0.1` (`ss -ltn`; SECURITY.md check 1 prints
`PASS`). So the remaining exposure is the host's own processes and users, and any container on
the engine (Docker Desktop's `host.docker.internal`) or on `k2-net`. A process running as the
maintainer also holds the Docker socket and so the whole engine; credentials on these services
matter against other host users and against containers, which is where the verdicts below are
set.
