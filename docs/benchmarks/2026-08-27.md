First v3 numbers. The v2 baseline ([2026-02-19](./2026-02-19-v2-baseline.md)) measured a
different pipeline (Kotlin → ClickHouse), so nothing here is a delta against it; the
comparison that matters is against the **predictions** in

should worry a reader: the Coinbase exchange→receive p99 reads **30 s**, and that is an
artefact of counting the venue's on-subscribe trade *snapshot* as live trades (§Latency —

six months plan 004 wanted (§Disk). The window is 6.5 h, not the 24 h the README bar asks
for: the maintainer cut it short on 2026-08-27 ("this is only a demo purpose … even 6 hours
is good enough"), so nothing here goes in the README as a steady-state claim.

should not observe `events[].type = snapshot` trades in

the lake. Until then, quote the book-snapshot p99 for Coinbase.

```sql
-- docker exec k2-spark-iceberg python3 -c "..."  (spark_conf.lake_session)
SELECT exchange, count(*) n,
  percentile_approx(lat_ms, 0.5) p50, percentile_approx(lat_ms, 0.99) p99,
```

<a id="b6"></a>**B6** — parity diff (the whole script: scratch, reproduced here)
```sql
CREATE OR REPLACE TEMP VIEW v AS
 SELECT 'binance' exchange, data.s symbol, CAST(data.t AS STRING) trade_id, conn_id, recv_ts_ns FROM lake.bronze.binance_trade
 UNION ALL SELECT 'kraken', d.symbol, CAST(d.trade_id AS STRING), conn_id, recv_ts_ns
   FROM lake.bronze.kraken_trade LATERAL VIEW explode(data) x AS d
 UNION ALL SELECT 'coinbase', t.product_id, t.trade_id, conn_id, recv_ts_ns
   FROM lake.bronze.coinbase_market_trades LATERAL VIEW explode(events) e AS ev LATERAL VIEW explode(ev.trades) x AS t;
-- counts
SELECT exchange, count(DISTINCT symbol, trade_id, conn_id) FROM v GROUP BY exchange;
SELECT exchange, count(DISTINCT symbol, trade_id, conn_id) FROM lake.bronze.trades GROUP BY exchange;
-- each direction: LEFT ANTI JOIN on (exchange, symbol, trade_id, conn_id), min/max recv_ts_ns, count(DISTINCT conn_id)
```
