# 2026-02-19 — v2 baseline

- **Stack commit:** `c3fd668` (Phase 7 Step 4, 2026-02-19) — the closest commit to the
  measurement window. Individual runs were not commit-stamped at the time.
- **Window:** 1 hour, 1× baseline load (~150 msg/s across three exchanges).
- **Uptime at measurement:** **cold start.** The stack had been up for minutes, not days.
  This invalidates every percentile below as a steady-state figure — see the caveat.
- **Host:** single developer workstation, Docker Engine + Compose v2.
- **Retro-compiled 2026-08-26** from the measurements recorded in
  `docs/operations/` and `docs/runbooks/` during Phase 7. It is a back-fill of numbers
  taken in February, not a fresh measurement session. Where a February document did not

  reads "not measured" rather than inventing it.

## Latency — exchange timestamp → ClickHouse Silver

Computed as `ingestion_timestamp - timestamp` on `k2.silver_trades`. **Includes internet
transit and exchange clock skew — this is not a trading-path latency measurement.** The
in-platform share of the budget is ~11 ms of the ~200 ms; the rest is round-trip to the
exchange.

| Exchange | n | p50 (ms) | p95 (ms) | p99 (ms) | Max (ms) | Command |
|----------|---|---------:|---------:|---------:|---------:|---------|
| Binance | 12 | 91 | 183 | 191 | 193 | [T1](#t1) |
| Coinbase | 13 | 87 | 188 | 197 | 199 | [T1](#t1) |
| Kraken | 12 | 71 | 162 | 170 | 172 | [T1](#t1) |

**Caveat — read before quoting these.** The stack was started cold and each exchange
contributed **12–13 trades**. At that sample size a "p99" is the slowest observation, not
a percentile. The numbers are directionally valid — the pipeline is in the low hundreds of
milliseconds, not seconds — and nothing more. Re-measure after a 24 h burn-in before any
of them is quoted as a platform figure.

**5× and 10× load tests were not run.** The method (Redpanda topic replay at the target
multiple, targets `<500 ms` and `<1 s` p99) is recorded in
[`../operations/latency-budgets.md`](../operations/latency-budgets.md) and remains
outstanding.

Supporting observation from the same run: Kafka Engine consumers healthy — 66 messages
read, 9 commits in the first five minutes from cold start, no exceptions in
`system.kafka_consumers`.

Source: [`../operations/latency-budgets.md`](../operations/latency-budgets.md).

## Failure modes and MTTR

Six modes, each deliberately induced and recovered on 2026-02-19. All six passed; worst
observed MTTR **32 s**. Recovery was automatic in every case — no manual step was needed
for any row.

| # | Failure | Target | Measured | Induce with |
|---|---------|--------|----------|-------------|
| 1 | Redpanda restart | <2 min | ~10 s | [T2](#t2) |
| 2 | ClickHouse restart | <3 min | ~32 s | [T2](#t2) |
| 3 | Feed handler crash | <1 min | ~30 s | [T2](#t2) |
| 4 | Spark / Prefect offload failure | <15 min | next scheduled run | [T3](#t3) |
| 5 | MinIO unavailable | <5 min | ~5 s | [T3](#t3) |
| 6 | Network partition | <5 min | ~20–30 s | [T4](#t4) |

Row 4 is a schedule, not a repair: the offload is idempotent against its PostgreSQL
watermark, so a failed cycle costs one 15-minute interval of cold-tier lag and nothing
else.

Source and per-mode recovery detail:
[`../runbooks/failure-recovery.md`](../runbooks/failure-recovery.md).

## Commands

<a id="t1"></a>**T1** — end-to-end lag per exchange. Full query in
[`../operations/data-inspection.md`](../operations/data-inspection.md#silver--unified-trades).

```bash
set -a && . ./.env && set +a
docker exec k2-clickhouse clickhouse-client --password "$CLICKHOUSE_PASSWORD" -q "
SELECT exchange,
       count()                                                       AS n,
       quantile(0.50)(dateDiff('millisecond', timestamp, ingestion_timestamp)) AS p50_ms,
       quantile(0.95)(dateDiff('millisecond', timestamp, ingestion_timestamp)) AS p95_ms,
       quantile(0.99)(dateDiff('millisecond', timestamp, ingestion_timestamp)) AS p99_ms,
       max(dateDiff('millisecond', timestamp, ingestion_timestamp))            AS max_ms
FROM k2.silver_trades
WHERE timestamp > now() - INTERVAL 1 HOUR
GROUP BY exchange ORDER BY exchange"
```

<a id="t2"></a>**T2** — induce a container restart, then take a row count either side of
the window and confirm continuity rather than just "it came back".

```bash
docker compose restart redpanda        # mode 1
docker compose restart clickhouse      # mode 2
docker compose restart feed-handler-binance   # mode 3
```

<a id="t3"></a>**T3** — induce an offload failure or MinIO outage.

```bash
docker compose stop minio              # mode 5; mode 4 follows from a failed offload cycle
docker compose start minio
```

<a id="t4"></a>**T4** — network partition.

```bash
docker network disconnect k2-net k2-feed-handler-binance
docker network connect    k2-net k2-feed-handler-binance
```

<a id="t5"></a>**T5** — declared limits vs live usage.

```bash
docker compose config | grep -A4 'limits:'          # declared
docker stats --no-stream --format \
  'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'    # actual
```

<a id="t6"></a>**T6** — a single offload run, timed. Prefect run history carries the same
figures at http://localhost:4200.

```bash
docker logs k2-prefect-worker --tail 200 | grep -i 'rows\|elapsed'
```
